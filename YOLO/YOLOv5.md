## 1. 基线：YOLOv5 概览

### 1.1 基本信息

| 项目 | 内容 |
|------|------|
| 作者/机构 | Ultralytics |
| 发表时间 | 2020 |
| 任务 | 通用目标检测（Anchor-based，单阶段） |

### 1.2 整体架构

YOLOv5 是典型的 **Backbone → Neck → Head** 三段式结构：

```
Input (B, 3, 640, 640)
    │
    ▼
┌─────────────────────────────────────┐
│  Backbone: CSPDarknet               │
│  提取 P3(80×80) / P4(40×40) / P5(20×20) 三层特征  │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│  Neck: PANet (FPN + 自底向上路径)    │
│  多尺度特征融合，输出三个增强特征层    │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│  Head: Detect                       │
│  每个尺度独立预测 3 个 anchor 的框+类别 │
└─────────────────────────────────────┘
    │
    ▼
Output: 三个尺度的 raw tensor
  P3: (B, 3×(5+nc), 80, 80)   ← 小目标
  P4: (B, 3×(5+nc), 40, 40)   ← 中目标
  P5: (B, 3×(5+nc), 20, 20)   ← 大目标
```

> **演进对比**
>
> | 版本 | 结构 | 问题/改进 |
> |------|------|----------|
> | **v1** | Backbone 直连 Head，7×7 单尺度输出 | 每 cell 只能预测 1 个类 + 2 个框，密集目标和小目标效果差 |
> | **v2** | 加入 Passthrough 层（26×26 特征拼到 13×13） | 首次引入 anchor 和 K-Means 聚类，但仍单尺度 |
> | **v3** | 3 尺度独立输出（13/26/52），类 FPN 上采样融合 | 多尺度检测成为标配，小目标 AP 大幅提升 |
> | **v4** | CSPDarknet + PANet + SPP，Neck 更完善 | 在 v3 三尺度基础上加强特征融合，精度逼近两阶段 |
> | **v5** | 同 v4 整体架构，模块工程化（C3/SPPF/SiLU） | 与 v4 结构等价，训练体验和部署生态更好 |

**每个预测向量 5+nc 维的含义：**

```
[tx, ty, tw, th, obj, cls_1, cls_2, ..., cls_nc]
 │   │   │   │    │    └──── 各类别得分（sigmoid 后）────┘
 │   │   │   │    └─ 目标置信度（是否有物体）
 │   │   │   └─ 高度偏移（相对 anchor）
 │   │   └─ 宽度偏移
 │   └─ y 偏移（相对 grid cell）
 └─ x 偏移（相对 grid cell）
```

### 1.4 YOLO 系列演进总览（v1 → v5）

理解 YOLOv5 最好的方式是把它放在整个 YOLO 家族的演进脉络中。每一代都在前一代的瓶颈上做针对性改进：

```
YOLOv1 (2016)  能跑起来，但小目标差、每格只能检 1 个目标
    ↓
YOLOv2 (2017)  引入 Anchor + Passthrough，召回率提升
    ↓
YOLOv3 (2018)  三尺度检测 + 类 FPN 结构，小目标大幅改善
    ↓
YOLOv4 (2020)  集大成：CSP + PANet + Mosaic + CIoU，精度追两阶段
    ↓
YOLOv5 (2020)  工程化精炼：继承 v4 精华，训练/部署更成熟
```

**各代核心差异一览：**

| 维度 | YOLOv1 | YOLOv2 | YOLOv3 | YOLOv4 | YOLOv5 |
|------|--------|--------|--------|--------|--------|
| **Backbone** | GoogLeNet 风格 24 层 | Darknet-19 | Darknet-53 | CSPDarknet53 | CSPDarknet（C3 模块） |
| **Neck** | 无 | Passthrough 层 | 类 FPN（3 路 upsample+concat） | PANet + SPP | PANet + SPPF |
| **检测尺度** | 1 个（7×7） | 1 个（13×13） | 3 个 | 3 个 | 3 个 |
| **Anchor** | 无（直接预测） | 5 个（K-Means 聚类） | 9 个（每尺度 3 个） | 9 个 | 9 个（autoanchor 自适应） |
| **激活函数** | Leaky ReLU | Leaky ReLU | Leaky ReLU | Mish | SiLU |
| **Box Loss** | MSE | MSE | MSE（后改 IoU） | CIoU | CIoU |
| **Cls Loss** | Softmax（类互斥） | Softmax | 独立 Sigmoid（多标签） | BCE | BCE |
| **数据增强** | 随机缩放/翻转 | 随机缩放/翻转 | 多尺度训练 | Mosaic + CutMix + SAT 等 | Mosaic + MixUp + HSV 等 |
| **标签分配** | GT 中心所在 cell | GT 中心 + anchor IoU | 每尺度 IoU 最大 1 个 anchor | 同 v3 + 改进 | Multi-positive 相邻 cell 扩展 |
| **输入尺寸** | 448 | 416 | 416 / 608 | 608 | 640（默认） |
| **框架** | Darknet (C) | Darknet (C) | Darknet (C) | Darknet / PyTorch | PyTorch |
| **COCO mAP@0.5:0.95** | ~19.5 | ~21.6 | ~33.0 | ~43.5 | ~37.4 (s) / ~50.7 (x) |

> YOLOv5 没有正式论文，是 Ultralytics 对 YOLOv4 思路的**工程化实现与优化**，并非全新的算法突破。其价值在于：更易用、训练更稳定、部署生态更完善。

**YOLOv5 相对 v4 的核心继承与改动：**

| 从 v4 继承 | v5 的改动 | 改动好处 |
|-----------|----------|----------|
| CSP 思想 | C3 模块（结构更简洁） | 代码更清晰，速度略快 |
| PANet 结构 | 相同，用 C3 替换 CSPLayer | 保持一致的多尺度融合能力 |
| Mosaic 增强 | 相同 + close_mosaic 策略 | 后期关闭 Mosaic 让模型在正常分布收敛 |
| CIoU Loss | 相同 | 保持定位精度 |
| SPP 块 | SPPF（串行 MaxPool） | 等效感受野，计算量更少 |
| Mish 激活 | SiLU 激活 | 精度接近，推理速度更快，硬件兼容性更好 |
| — | EMA 权重平均 | 验证/推理更稳定，+0.5~1 mAP |
| — | AutoAnchor 检查 | 自定义数据集自动验证 anchor 适配度 |
| — | Multi-positive 相邻 cell | 正样本更多，recall 更高 |
| — | n/s/m/l/x 缩放系列 | 一套代码覆盖全速度-精度谱 |

## 2. 核心模块详解

### 2.1 基础卷积块 Conv

YOLOv5 中最基本的构建单元：

```
Input
  ↓
Conv 2d (k×k, stride=s, padding=auto)
  ↓
BatchNorm 2d
  ↓
SiLU 激活（也叫 Swish: x · sigmoid(x)）
  ↓
Output
```

- **无偏置**：Conv 层 `bias=False`，由 BN 承担偏移
- **SiLU 优于 ReLU**：平滑、非单调，梯度传播更好
- **自动 padding**：`pad = k // 2`，保证 stride=1 时尺寸不变

> **演进对比：激活函数**
>
> | 版本 | 激活函数 | 特点 |
> |------|----------|------|
> | **v1/v2/v3** | Leaky ReLU（负区间斜率 0.1） | 简单高效，但负区间梯度恒定为 0.1，信息利用不充分 |
> | **v4** | Mish（x · tanh(softplus(x))） | 处处平滑、非单调，实验精度更高，但计算量比 ReLU 大 ~15% |
> | **v5** | SiLU / Swish（x · sigmoid(x)） | 与 Mish 性质类似（平滑、非单调），PyTorch 原生支持，推理更快 |
>
> **为什么 v5 选 SiLU 而非 v4 的 Mish？** Mish 精度略优但无原生 CUDA 算子，SiLU 在精度和速度间取得更好平衡，且与 Transformer 等现代架构统一。

> **演进对比：Conv-BN 结构**
>
> | 版本 | BN | 说明 |
> |------|-----|------|
> | **v1** | 无 BN | 训练不稳定，收敛慢 |
> | **v2** | 有 BN | 加速收敛，允许更大学习率 |
> | **v3~v5** | Conv-BN-Activation 标准组合 | 成为目标检测标配 |

### 2.2 Focus 模块（早期版本）

早期 YOLOv5 用 Focus 做**无损下采样**，将空间信息转入通道：

```
输入: (B, 3, 640, 640)

切片操作（类似 pixel unshuffle）:
  slice_0 = x[..., 0::2, 0::2]  → (B, 3, 320, 320)  左上像素
  slice_1 = x[..., 1::2, 0::2]  → (B, 3, 320, 320)  右上
  slice_2 = x[..., 0::2, 1::2]  → (B, 3, 320, 320)  左下
  slice_3 = x[..., 1::2, 1::2]  → (B, 3, 320, 320)  右下

拼接: (B, 12, 320, 320)
  ↓
Conv 3×3, stride=1 → (B, 64, 320, 320)
```

**作用**：stride=2 下采样但不丢信息（4 个像素合成 4 个通道）。  
**现状**：新版本已用 `Conv 6×6, stride=2` 替代 Focus，避免某些硬件导出兼容问题，功能等价。

### 2.3 Bottleneck（残差瓶颈）

```
Input (C 通道)
  ├────────────────────────────── (shortcut, 仅当 C_in == C_out)
  │                                      │
  ↓                                      │
Conv 1×1 → C_out/2 通道                  │
  ↓                                      │
Conv 3×3 → C_out 通道                    │
  ↓                                      │
  + ←────────────────────────────────────┘
  ↓
Output
```

- 1×1 先**降维**，3×3 提取空间特征，再**残差相加**
- 减少计算量的同时保留梯度通路，缓解深层网络退化

> **演进对比**
>
> | 版本 | 残差结构 | 说明 |
> |------|----------|------|
> | **v1** | 无残差，24 层普通卷积 | 网络不能太深，否则梯度消失 |
> | **v2** | 无残差，Darknet-19 | 仍靠 BN 缓解，深度受限 |
> | **v3** | 无残差，Darknet-53（53 层） | 靠 BN + 多尺度输出缓解深层问题 |
> | **v4/v5** | Bottleneck 残差 + CSP/C3 | 残差连接让 backbone 可以更深，梯度直达浅层 |

### 2.4 C3 模块（Cross Stage Partial）

YOLOv5 的核心重复单元，替代 YOLOv4 的 CSP 模块：

```
Input (C1 通道)
  │
  ├─ Conv 1×1 → C2 通道 ──→ n × Bottleneck ──→ (分支 A)
  │
  └─ Conv 1×1 → C2 通道 ──────────────────────→ (分支 B, 直连)
  │
  Concat [A, B] → 2×C2 通道
  │
  Conv 1×1 → C3 通道
  │
  Output
```

**设计思想（CSP 核心）：**

1. 输入拆成两路：一路过 Bottleneck 堆叠做**深层特征提取**，一路**直连**保留浅层梯度
2. 两路 Concat 后 1×1 融合
3. 相比全部走 Bottleneck，**减少冗余梯度复制**，训练更稳定、推理更快

> **演进对比：CSP 结构**
>
> | 版本 | Backbone 核心 | 问题/改进 |
> |------|--------------|----------|
> | **v1** | 24 层类 GoogLeNet（1×1 + 3×3 交替） | 结构简单，特征提取能力弱 |
> | **v2** | Darknet-19（19 层 + 1×1 降维） | 更轻量，加入 1×1 瓶颈减少计算 |
> | **v3** | Darknet-53（53 层，每 2 个 3×3 替代 1 个 5×5） | 更深更强，但梯度冗余问题仍存在 |
> | **v4** | CSPDarknet53（CSP 拆分梯度流） | CSP 将特征拆为两路，减少 20% 计算量，精度提升 |
> | **v5** | CSPDarknet（C3 模块，CSP 简化版） | 与 v4 CSP 思想一致，模块更模块化、yaml 配置更灵活 |
>
> **CSP 的核心好处**：传统深层网络中，反向传播时梯度被大量复制到每个 Bottleneck 分支，造成冗余计算。CSP 让一路直连、一路走 Bottleneck，梯度不再重复复制，**训练更快、推理更轻**。

**YOLOv5 中 C3 的变体：**

| 变体 | 区别 | 出现位置 |
|------|------|----------|
| C3 | 标准 Bottleneck 堆叠 | Backbone、Neck 主体 |
| C3x | Bottleneck 中 3×3 换为两个 1×1（Cross Conv） | 大模型 |
| C3TR | Bottleneck 换为 Transformer Block | 实验性 |
| C3SPP | 内部嵌 SPP 层 | 早期版本 |
| C3Ghost | 内部用 GhostConv | 轻量化 |

### 2.5 SPPF 模块（Spatial Pyramid Pooling - Fast）

替代 YOLOv4 的 SPP，加速特征融合：

```
Input
  ↓
Conv 1×1 → C/2 通道
  ↓
MaxPool 5×5, stride=1, padding=2  ──→ out1
  ↓ (输入 = out1)
MaxPool 5×5  ──→ out2
  ↓ (输入 = out2)
MaxPool 5×5  ──→ out3
  ↓
Concat [原始, out1, out2, out3]  → 4×C/2 通道
  ↓
Conv 1×1 → C 通道
  ↓
Output
```

**作用**：等效于并行 MaxPool(5/9/13)，但**串行复用**计算，速度更快。  
**意义**：扩大感受野，让 P5 层能"看到"更大范围的上下文，有利于检测大目标。

> **演进对比：SPP 系列**
>
> | 版本 | 多尺度池化 | 说明 |
> |------|-----------|------|
> | **v1~v3** | 无 SPP | P5 层感受野有限，大目标上下文不足 |
> | **v4** | SPP（并行 MaxPool k=5/9/13） | 在 backbone 顶端拼接多尺度池化特征，扩大感受野 |
> | **v5** | SPPF（串行 3 次 MaxPool k=5） | 数学上等效于 k=5/9/13 三级感受野，但串行复用只需 1 次 MaxPool 的参数，**速度提升 ~30%** |

## 3. Backbone：CSPDarknet 逐层结构

以 **YOLOv5s** 为例（`yolov5s.yaml`），通道数 `[64, 128, 256, 512, 1024]`：

```
层   操作                        输出尺寸        说明
─────────────────────────────────────────────────────────────
 0   Conv 6×6, s=2               320×320×64     初始下采样（替代 Focus）
 1   Conv 3×3, s=2               160×160×128    ↓2
 2   C3 × 3                      160×160×128    深层特征提取
 3   Conv 3×3, s=2                80×80×256     ↓2  ──→ 保存为 P3 特征源
 4   C3 × 6                       80×80×256
 5   Conv 3×3, s=2                40×40×512     ↓2  ──→ 保存为 P4 特征源
 6   C3 × 9                       40×40×512
 7   Conv 3×3, s=2                20×20×1024    ↓2  ──→ 保存为 P5 特征源
 8   C3 × 3                       20×20×1024
 9   SPPF                         20×20×1024    最大感受野
```

**三个输出特征层与 stride 关系：**

| 特征 | 尺寸 (640 输入) | Stride | 感受野 | 适合目标 |
|------|----------------|--------|--------|----------|
| P3 | 80 × 80 | 8 | 小 | 小目标（< 32×32 px） |
| P4 | 40 × 40 | 16 | 中 | 中等目标 |
| P5 | 20 × 20 | 32 | 大 | 大目标 |

**不同型号差异（depth × width 缩放）：**

| 型号 | depth_multiple | width_multiple | C3 重复次数(层2/4/6/8) |
|------|---------------|----------------|----------------------|
| n | 0.33 | 0.25 | 1/2/2/1 |
| s | 0.33 | 0.50 | 1/2/3/1 |
| m | 0.67 | 0.75 | 2/4/6/2 |
| l | 1.00 | 1.00 | 3/6/9/3 |
| x | 1.33 | 1.25 | 4/8/12/4 |

> **演进对比：Backbone 深度与缩放**
>
> | 版本 | Backbone | 层数 | 缩放策略 |
> |------|----------|------|----------|
> | **v1** | 自定义 24 层 | 24 | 无，单一模型 |
> | **v2** | Darknet-19 | 19 | 无，单一模型 |
> | **v3** | Darknet-53 | 53 | 无，单一模型（提供 608 输入变体） |
> | **v4** | CSPDarknet53 | 53+ | 手动调 width/depth |
> | **v5** | CSPDarknet | 可变 | **depth_multiple × width_multiple 统一缩放**，n/s/m/l/x 五档 |
>
> **v5 缩放的好处**：一套 yaml 模板 + 两个缩放系数，即可生成从轻量到重量级的完整模型族，无需为每个型号单独设计网络，工程维护成本极低。

## 4. Neck：PANet 特征融合

PANet = **FPN（自顶向下）** + **PAN（自底向上）**，解决不同尺度特征语义与定位信息不对齐的问题。

### 4.1 自顶向下路径（FPN）

```
P5 (20×20, 1024ch) ── 语义最强、分辨率最低
  │
  Conv 1×1 → 512ch
  │
  Upsample ×2 (nearest)  → 40×40
  │
  Concat ← P4 (40×40, 512ch)    ← 融合中层特征
  │
  C3 → 512ch
  │
  Upsample ×2  → 80×80
  │
  Concat ← P3 (80×80, 256ch)    ← 融合浅层特征
  │
  C3 → 256ch  ──→ 输出 N3 (80×80)  用于检测小目标
```

**作用**：把 P5 的**高层语义**传递给 P3/P4，让浅层特征也具备分类能力。

### 4.2 自底向上路径（PAN）

```
N3 (80×80, 256ch)    ← 来自 FPN 输出
  │
  Conv 3×3, s=2  → 40×40
  │
  Concat ← N4 中间特征 (40×40, 512ch)
  │
  C3 → 512ch  ──→ 输出 N4 (40×40)  用于检测中目标
  │
  Conv 3×3, s=2  → 20×20
  │
  Concat ← P5 (20×20, 1024ch)
  │
  C3 → 1024ch ──→ 输出 N5 (20×20)  用于检测大目标
```

**作用**：把 N3 的**高分辨率定位信息**回传 P5，增强大目标的定位精度。

### 4.3 为什么 PANet 比纯 FPN 更好？

```
纯 FPN：  只有 top-down，浅层有语义但定位信息在深层
PANet：   top-down + bottom-up，每个尺度同时有语义 + 定位
```

对小目标尤其重要：P3 经过 bottom-up 路径再次增强后，小目标的 AP 通常比纯 FPN 高 1~2 点。

> **演进对比：Neck 特征融合**
>
> | 版本 | 特征融合方式 | 问题/改进 |
> |------|-------------|----------|
> | **v1** | 无 Neck，Backbone 最后一层直接接 Head | 只有单一尺度特征，小目标完全丢失 |
> | **v2** | Passthrough 层：26×26 特征 rearrange 后 concat 到 13×13 | 首次尝试融合浅层特征，但方式粗糙（rearrange 而非语义融合） |
> | **v3** | 3 路独立检测 + 上采样 concat（FPN 雏形） | 每个尺度从 backbone 不同层取特征并上采样融合，小目标 AP 从 ~19 提升到 ~33 |
> | **v4** | PANet = FPN + 自底向上路径 + SPP | 在 v3 基础上增加 bottom-up 路径，每个尺度同时获得语义 + 定位信息 |
> | **v5** | 同 v4 PANet，模块换为 C3 | 保持 v4 的多尺度融合能力，模块更简洁 |
>
> **为什么 v2 的 Passthrough 不够？** Passthrough 只是把高分辨率特征"拼"到低分辨率上，没有做语义层面的融合（无 Conv 学习如何组合）。v3 的 FPN 通过 Conv + Upsample 真正实现了跨层语义传递。
>
> **为什么 v4 在 v3 的 FPN 上还要加 bottom-up？** 纯 FPN 的 top-down 路径让浅层获得了语义，但**浅层的高分辨率定位信息没有传递到深层**。PAN 的 bottom-up 补上了这条路，使 P5 层也能受益于高分辨率定位特征。

## 5. Head：Detect 检测头

### 5.1 结构

三个尺度各一个 Detect 层，结构相同：

```
输入特征 (B, C, H, W)
  ↓
Conv 1×1 → (B, na×(5+nc), H, W)
  ↓
Reshape → (B, na, 5+nc, H, W)
  ↓
Permute → (B, na, H, W, 5+nc)
```

- `na = 3`：每个 cell 预测 3 个 anchor
- `nc`：类别数（COCO 为 80，自定义数据集自行设定）

> **演进对比：检测头**
>
> | 版本 | 预测方式 | 每 cell 预测数 | 类别预测 |
> |------|----------|---------------|----------|
> | **v1** | 无 anchor，直接预测 (x,y,w,h) + conf + cls | 2 个 bbox + 20 类 softmax | Softmax（类互斥，一个目标只能属 1 类） |
> | **v2** | 引入 anchor，预测偏移 (tx,ty,tw,th) | 5 个 anchor | Softmax |
> | **v3** | 同 v2，3 尺度各 3 个 anchor | 每尺度 3 个 anchor | **独立 Sigmoid**（支持多标签） |
> | **v4/v5** | 同 v3 | 每尺度 3 个 anchor | 独立 Sigmoid + BCE Loss |
>
> **v1 → v2 引入 anchor 的好处**：v1 直接预测绝对坐标，网络需要从像素级学习框的位置和大小，收敛困难。v2 的 anchor 提供了**形状先验**，网络只需学习偏移量，大幅降低回归难度。
>
> **v2 → v3 改用 Sigmoid 的好处**：Softmax 假设类互斥（一个目标只能属于一个类），但检测中存在"人穿 T 恤"等可重叠属性。独立 Sigmoid 让每个类独立判断，更灵活。

### 5.2 Anchor 设计

YOLOv5 在 COCO 上用 K-Means 聚类得到 9 个 anchor，按面积从小到大排列，分配到三个尺度：

| 尺度 | Stride | Anchor (w×h) | 对应目标大小 |
|------|--------|--------------|-------------|
| P3 | 8 | (10,13), (16,30), (33,23) | 小 |
| P4 | 16 | (30,61), (62,45), (59,119) | 中 |
| P5 | 32 | (116,90), (156,198), (373,326) | 大 |

**自定义数据集必须重新聚类 anchor**（`utils/autoanchor.py`），否则默认 COCO anchor 与数据尺度不匹配，精度会明显下降。

```bash
# 自动聚类 anchor 并检查当前 anchor 适配度
python utils/autoanchor.py --data data/custom.yaml
```

> **演进对比：Anchor 机制**
>
> | 版本 | Anchor 数量 | 聚类方式 | 说明 |
> |------|------------|----------|------|
> | **v1** | 无 anchor | — | 直接预测宽高，无形状先验 |
> | **v2** | 5 个（单尺度） | K-Means 聚类训练集 GT 框 | 首次引入 anchor 概念，来自 Faster R-CNN |
> | **v3** | 9 个（3 尺度 × 3） | K-Means，按面积排序后分配到各尺度 | 多尺度各配 3 个不同形状的 anchor |
> | **v4** | 9 个 | 同 v3 | 继承 v3 策略 |
> | **v5** | 9 个 | K-Means + **AutoAnchor 自动检查** | 训练前自动评估 anchor 与数据的匹配度（best possible recall），低于 0.98 则重新聚类 |
>
> **为什么需要 K-Means 聚类 anchor？** 如果 anchor 形状与数据集中目标的典型形状差异大，网络需要学习很大的偏移量才能拟合 GT，回归困难、收敛慢。聚类使 anchor 接近数据分布，**偏移量更小、更容易学**。

### 5.3 推理时的坐标解码

网络输出的是**相对偏移量**，需要解码为绝对像素坐标：

```
已知：
  grid cell 索引 (gx, gy)
  stride s（P3=8, P4=16, P5=32）
  anchor 尺寸 (aw, ah)
  网络 raw 输出 (tx, ty, tw, th)  （未经 sigmoid）

解码公式：
  bx = (2 · σ(tx) - 0.5 + gx) × s
  by = (2 · σ(ty) - 0.5 + gy) × s
  bw = (2 · σ(tw))² × aw
  bh = (2 · σ(th))² × ah
```

**公式设计意图：**

| 项 | 设计 | 作用 |
|----|------|------|
| `2·σ(t) - 0.5` | sigmoid 映射到 (-0.5, 1.5) | 允许预测框中心超出当前 cell 范围，覆盖相邻 cell 的目标 |
| `(2·σ(t))²` | 平方放大 | 宽高的动态范围更大，能覆盖从小到大的各种 anchor 比例 |
| `× s` | 乘 stride | 从 feature map 坐标映射回原图坐标 |

**置信度计算：**

```
obj_conf = σ(obj_logit)          # 是否有物体
cls_conf = σ(cls_logit)          # 各类别概率
final_conf = obj_conf × cls_conf  # 最终得分
```

> **演进对比：坐标解码公式**
>
> | 版本 | 中心 (x,y) 解码 | 宽高 (w,h) 解码 |
> |------|----------------|----------------|
> | **v1** | 直接 sigmoid → cell 内相对坐标 | 直接 exp 或 sigmoid → 绝对值 |
> | **v2** | sigmoid(tx) + cell 偏移 | exp(tw) × anchor_w |
> | **v3** | sigmoid(tx) + cell 偏移 | exp(tw) × anchor_w |
> | **v4** | **(2·σ(tx) - 0.5) + cell 偏移** | **(2·σ(tw))² × anchor_w** |
> | **v5** | 同 v4 | 同 v4 |
>
> **v3 → v4 解码公式改进的好处**：
> - `2·σ(t) - 0.5` 将偏移范围从 (0,1) 扩展到 (-0.5, 1.5)，允许中心**超出当前 cell 一个 cell 宽度**，减少边界目标的漏检
> - `(2·σ(t))²` 替代 `exp(t)` 限制宽高范围，避免 exp 爆炸导致框过大，训练更稳定

### 5.4 Detect 层初始化与 Stride 计算

文档前面讲了 Detect 的结构和解码，但有两个**训练稳定性**相关的处理容易忽略：

#### Stride 自动计算

模型构建时，Detect 层并**非硬编码** stride=8/16/32，而是前向传播一次 dummy 输入自动推断：

```
dummy 输入 (1, 3, 256, 256)
  → 前向传播，记录 P3/P4/P5 输出 feature map 尺寸
  → stride = 输入尺寸 / feature map 尺寸
  → 通常得到 [8, 16, 32]
```

**好处**：改 yaml 结构或输入尺寸时，stride 自动适配，anchor 也会按 stride 重新排序分配，无需手动改配置。

#### Detect 层 Bias 初始化

Detect 的 1×1 卷积 bias 有特殊初始化，对初期训练至关重要：

```
obj bias  ← -log((1 - pi) / pi)，其中 pi = 0.01
            → 初始 obj sigmoid ≈ 0.01，即"默认认为没有物体"

cls bias  ← log(5 / nc / (640/s)²)
            → 根据类别数和 stride 调整，避免初期 cls 偏高
```

**为什么要这样初始化？**

- 25,200 个预测点中只有 ~50 个是正样本，若 obj 初始值接近 0.5，初期会产生海量 FP，obj loss 梯度爆炸
- 将 obj 初始压低到 ~0.01，与真实正负比（1:500）接近，**训练初期更稳定**
- 这是 YOLOv5 相比 v3/v4 训练"开箱即用"不出 NaN 的细节之一

#### Anchor 与 Stride 的绑定

```python
# 每个尺度的 anchor 在 loss 计算时会除以对应 stride，归一化到 feature map 空间
anchors[i] = anchor_list[i] / stride[i]
```

保证不同尺度的 anchor 在 feature map 坐标系下尺度一致，标签分配和 loss 计算才正确。

## 6. 训练全流程处理

### 6.1 数据加载与预处理

```
原始图片 + YOLO 格式标签 (class, cx, cy, w, h)  归一化到 [0,1]
    │
    ▼
Letterbox 缩放
  - 保持宽高比，等比缩放到目标尺寸内
  - 不足部分用灰色 (114,114,114) 填充
  - 同时调整标签坐标
    │
    ▼
数据增强（训练时）
  - Mosaic / MixUp / HSV / 翻转 / 平移 / 缩放 ...
    │
    ▼
归一化: pixel / 255.0
    │
    ▼
Tensor: (B, 3, H, W)   默认 H=W=640
```

**Letterbox 细节（推理同样使用）：**

```
原图 800×600，目标 640×640：
  scale = min(640/800, 640/600) = 0.8
  新尺寸 = 640×480
  上下各填充 (640-480)/2 = 80 像素灰边

  标签 cx 不变，cy' = (cy × 480 + 80) / 640
```

> **演进对比：输入预处理**
>
> | 版本 | 缩放方式 | 说明 |
> |------|----------|------|
> | **v1~v3** | 直接 resize 到固定尺寸（拉伸变形） | 简单但改变宽高比，框变形 |
> | **v4/v5** | **Letterbox**（等比缩放 + 灰边填充） | 保持宽高比，目标不变形；推理时需将坐标映射回原图 |
>
> Letterbox 来自 v4 的改进，v5 完整继承。对非正方形图片（如 1920×1080 监控画面）尤其重要。

### 6.2 Mosaic 增强（核心）

```
┌──────────┬──────────┐
│  图 A    │   图 B   │   4 张图随机缩放后拼成 2×2
│          │          │   拼接中心点随机（在图像 1/3 ~ 2/3 范围内）
├──────────┼──────────┤
│  图 C    │   图 D   │   每张图的标签坐标同步变换
└──────────┴──────────┘
         ↓
    640×640 输出
```

**为什么 Mosaic 有效：**

1. 单 batch 内目标数量 ×4，BN 统计更稳定
2. 目标尺度差异极大，模型学会多尺度检测
3. 截断目标增多，提升对部分遮挡目标的鲁棒性
4. 背景组合多样，减少过拟合

**关闭 Mosaic 的时机**：最后 `close_mosaic` 个 epoch（默认 10）关闭，让模型在正常分布上收敛。

> **演进对比：数据增强**
>
> | 版本 | 主要增强 | 说明 |
> |------|----------|------|
> | **v1** | 随机缩放、平移、翻转 | 基础几何增强 |
> | **v2** | 同 v1 + **多尺度训练**（每 10 batch 换尺寸） | 让模型适应不同分辨率 |
> | **v3** | 同 v2 + 随机调整宽高比 | 进一步增加尺度多样性 |
> | **v4** | **Mosaic** + CutMix + SAT + DropBlock 等 | "Bag of Freebies" 策略，零推理成本提升精度 |
> | **v5** | Mosaic + **MixUp** + HSV + 翻转/平移/缩放 | 继承 v4 Mosaic，新增 MixUp；最后 N epoch 关闭 Mosaic |
>
> **Mosaic 的来源与好处**：YOLOv4 首次提出并验证 Mosaic 增强，YOLOv5 完整继承。核心价值是在**不增加推理成本**的前提下，单 batch 内目标数 ×4、背景组合极大丰富，COCO 上通常 +2~3 mAP。
>
> **v5 新增 close_mosaic 的意义**：v4 全程使用 Mosaic，导致训练末期模型仍在"拼接图"分布上优化。v5 最后 10 epoch 关闭 Mosaic，让模型在**真实单图分布**上微调，减少 train-test 分布差异。

### 6.3 MixUp 增强

```
混合图像:  I' = λ·I₁ + (1-λ)·I₂       λ ~ Beta(32, 32)，接近 0.5
混合标签:  两组标签直接合并（不做坐标插值）
```

即一张图里同时存在两组框，训练模型对"叠加场景"的判别能力。

### 6.3.1 其他数据增强（文档前仅列名，此处补全）

除 Mosaic / MixUp 外，YOLOv5 默认还启用以下增强（在 `utils/augmentations.py`）：

| 增强 | 参数（hyp.yaml） | 操作 | 作用 |
|------|-----------------|------|------|
| **HSV 抖动** | `hsv_h/s/v` = 0.015/0.7/0.4 | 随机调整色调/饱和度/明度 | 光照变化鲁棒性（白天/夜晚/阴影） |
| **随机翻转** | `fliplr` = 0.5 | 50% 概率水平翻转 | 镜像对称目标（人、车等） |
| **随机平移** | `translate` = 0.1 | 平移 ±10% 图像尺寸 | 目标不总在画面中心 |
| **随机缩放** | `scale` = 0.5 | 缩放 0.5~1.5 倍 | 尺度多样性 |
| **随机透视** | `perspective` = 0.0（默认关） | 四顶点扰动模拟视角变化 | 倾斜/俯拍场景，设 >0 启用 |
| **Copy-Paste** | 默认未启用 | 实例级粘贴到其他图 | v4 有，v5 需手动接入或改代码 |

**HSV 增强细节：**

```
H' = H × (1 + random(-0.015, 0.015))   色调微调
S' = S × (1 + random(-0.7, 0.7))        饱和度大幅抖动
V' = V × (1 + random(-0.4, 0.4))        明度中等抖动
```

HSV 只改图像不改标签坐标，计算成本极低，几乎总是正收益。

### 6.3.3 数据加载优化选项

| 选项 | 命令 | 作用 |
|------|------|------|

这是影响精度的**关键步骤**，在 `utils/loss.py` 的 `build_targets` 中实现。

#### 6.4.1 为什么需要正负样本分配？

YOLOv5 属于**密集预测（Dense Prediction）**：对 feature map 上**每一个 grid cell × 每一个 anchor** 都输出一组预测。

以 640×640 输入为例，预测点总数为：

```
P3: 80 × 80 × 3 = 19,200
P4: 40 × 40 × 3 =  4,800
P5: 20 × 20 × 3 =  1,200
─────────────────────────
合计:              25,200 个预测点 / 每张图
```

但一张图通常只有 **几个到几十个** 真实目标。网络必须知道：

- 哪些预测点应该**努力拟合 GT**（正样本）
- 哪些预测点应该**学会输出"这里没有物体"**（负样本）

如果不做分配，25,000 个预测点都没有明确监督信号，模型无法收敛。

> **演进对比：预测密度**
>
> | 版本 | 预测点数量 (COCO) | 说明 |
> |------|------------------|------|
> | **v1** | 7×7×2 = **98** | 极稀疏，大量目标被遗漏 |
> | **v2** | 13×13×5 = **845** | 引入 anchor 后密度提升 |
> | **v3** | (13²+26²+52²)×3 = **10,647** | 三尺度使密度 ×10+ |
> | **v4/v5** | (20²+40²+80²)×3 = **25,200** | 更高分辨率输入 + 三尺度，密度进一步增加 |
>
> 预测点越多 → 潜在 recall 越高，但正负样本越不平衡 → 需要更好的标签分配和 loss 设计。

```
                    25,200 个预测点
                          │
          ┌───────────────┼───────────────┐
          ▼               ▼               ▼
       正样本           负样本         （极少忽略）
    匹配到 GT 框      未匹配任何 GT
    学 box+cls+obj    只学 obj=0
    通常 ~20~100 个   通常 ~25,000 个
```

#### 6.4.2 三类样本及其监督信号

| 类型 | 判定条件 | obj 目标 | box loss | cls loss | 作用 |
|------|----------|----------|----------|----------|------|
| **正样本** | 成功匹配到某个 GT | 1.0 | ✓ 计算 CIoU | ✓ 计算 BCE | 学会"这里有物体 + 框在哪 + 是什么类" |
| **负样本** | 未匹配任何 GT | 0.0 | ✗ 不计算 | ✗ 不计算 | 学会"这里是背景" |
| **忽略样本** | YOLOv5 默认几乎不用 | — | — | — | 其他检测器中用于 IoU 模糊区间 |

**为什么负样本只参与 obj loss，不算 box/cls loss？**

- 负样本位置**没有 GT 框**，无法定义"正确的框"和"正确的类别"
- 若对负样本也算 box loss，网络会被迫把背景区域回归成某个随机框，产生冲突梯度
- 因此负样本的唯一任务就是：**压低 objectness 得分**，让模型学会区分前景/背景

**为什么 obj 和 cls 要分开？**

```
obj  → "这个位置有没有物体？"        → 所有样本都参与（正样本趋近 1，负样本趋近 0）
cls  → "如果有，是什么类别？"        → 仅正样本参与
box  → "如果有，框的精确位置在哪？"   → 仅正样本参与
```

这种解耦让网络先学会**定位**（obj），再学会**分类**（cls），任务更清晰。最终推理置信度 = `obj × cls`，两者都高才输出。

> **演进对比：obj 与 cls 的关系**
>
> | 版本 | 置信度计算 | 说明 |
> |------|-----------|------|
> | **v1** | conf 与 cls 耦合在一个 softmax 中 | 无法区分"有物体但不知道类"和"没物体" |
> | **v2** | 分离 conf 和 cls，但 cls 仍用 Softmax | 部分解耦 |
> | **v3~v5** | **obj × cls（独立 Sigmoid）** | 完全解耦：obj 负责"有没有"，cls 负责"是什么" |
>
> **v3 解耦的好处**：推理时可以分别控制 obj 和 cls 的阈值；训练时 obj loss 在所有样本上计算（正负样本都有明确 obj 目标），而 cls loss 只在正样本上计算，避免背景区域的分类噪声。

#### 6.4.3 Step 1：Anchor 宽高比筛选

```
r = max( w_gt/aw, aw/w_gt, h_gt/ah, ah/h_gt )

保留 r < anchor_t 的 anchor 作为候选（默认 anchor_t = 4.0）
```

**为什么用宽高比，而不是 IoU？**

- 标签分配阶段，GT 框位置已知，但 anchor 是**固定先验框**，位于 cell 中心
- 此时 anchor 与 GT 的位置可能差很远，算 IoU 没有意义（可能为 0）
- **宽高比**只比较"形状是否匹配"，与位置无关，能正确判断"这个 anchor 适不适合回归这个 GT"

**数值示例：**

```
GT 框: w=40, h=80（竖长形）
Anchor A: aw=16, ah=30 → r = max(40/16, 16/40, 80/30, 30/80) = max(2.5, 0.4, 2.67, 0.375) = 2.67 ✓ (< 4.0，匹配)
Anchor B: aw=116, ah=90 → r = max(40/116, 116/40, 80/90, 90/80) = max(0.34, 2.9, 0.89, 1.125) = 2.9 ✓ (< 4.0，也匹配)
Anchor C: aw=373, ah=326 → r = max(40/373, 373/40, 80/326, 326/80) = max(0.11, 9.3, ...) = 9.3 ✗ (太大，不匹配)
```

**为什么 anchor_t 设为 4.0（允许 4 倍差异）？**

- 太严格（如 2.0）：很多 GT 匹配不到 anchor → 正样本不足 → 漏检
- 太宽松（如 8.0）：形状差异很大的 anchor 也被匹配 → 回归难度大 → 定位不准
- 4.0 是经验值，允许一定尺度弹性，同时保证 anchor 形状不会差太远

**为什么同一个 GT 可以匹配多个 anchor？**

- 同一尺度层有 3 个 anchor，宽高比不同，可能同时满足 r < 4.0
- 多个 anchor 同时学习同一个 GT → **增加正样本数量**，加速收敛
- 推理时多个 anchor 可能对同一 GT 都产生高置信度预测 → 靠 **NMS** 去重（见 §7.2）

#### 6.4.4 Step 2：Grid Cell 中心分配

```
gx = cx × W_fm        # GT 中心 x 映射到 feature map 坐标（浮点数）
gy = cy × H_fm        # GT 中心 y 映射到 feature map 坐标（浮点数）

gi = floor(gx)        # 中心所在 cell 的列索引
gj = floor(gy)        # 中心所在 cell 的行索引
```

**为什么按 GT 中心分配 cell，而不是按 IoU 最大？**

| 策略 | 做法 | 优缺点 |
|------|------|--------|
| 中心分配（YOLO 系列） | GT 中心落在哪个 cell，就由该 cell 负责 | 简单、快速、确定性；一个 GT 对应明确的 cell |
| Max-IoU 分配（Faster R-CNN） | 与 GT IoU 最大的 anchor 为正样本 | 更灵活，但计算量大，单阶段检测中较少用 |
| 动态分配（SimOTA 等） | 根据分类+回归综合代价匹配 | 更优但复杂，YOLOX/YOLOv8 采用 |

YOLOv5 选择中心分配：单阶段检测追求速度，中心分配 O(1) 即可完成，且与 anchor 机制配合良好。

> **演进对比：Cell 分配策略**
>
> | 版本 | 分配规则 | 说明 |
> |------|----------|------|
> | **v1** | GT 中心所在 cell 负责（无 anchor） | 最简单，但一个 cell 只能检 1 类 2 框 |
> | **v2** | GT 中心所在 cell + anchor IoU 匹配 | 引入 anchor 后每 cell 可检 5 个不同形状的目标 |
> | **v3** | GT 中心 cell + 每尺度 IoU 最大的 1 个 anchor | 三尺度各 1 个 anchor，共 3 个正样本/GT |
> | **v4** | 同 v3，增加 CIoU 匹配辅助 | 匹配策略基本继承 v3 |
> | **v5** | 中心 cell + **相邻 cell 扩展** + 宽高比筛选 | 正样本数从 3 个/GT 增加到最多 9 个/GT |

#### 6.4.5 Step 3：相邻 Cell 扩展（Multi-positive 策略）

这是 YOLOv5 相比 YOLOv3 **最重要的训练改进之一**。

```
gxi = gx - floor(gx)    # GT 中心在 cell 内的相对 x 偏移，范围 [0, 1)
gyi = gy - floor(gy)    # GT 中心在 cell 内的相对 y 偏移，范围 [0, 1)

扩展规则（以 gx 方向为例）:
  若 gxi < 0.5 且 gi > 0         → 额外匹配左侧 cell (gi-1, gj)
  若 gxi >= 0.5 且 gi < W_fm-1   → 额外匹配右侧 cell (gi+1, gj)
  （y 方向同理，匹配上方或下方 cell）
```

**示意图：**

```
        列 gi-1      列 gi       列 gi+1
      ┌─────────┬─────────┬─────────┐
行 gj-1│         │  扩展↑  │         │  gxi < 0.5 → 也匹配左侧
      ├─────────┼─────────┼─────────┤  gxi >= 0.5 → 也匹配右侧
行 gj  │  扩展←  │    ★    │  扩展→  │  gyi < 0.5 → 也匹配上方
      │         │  GT 中心 │         │  gyi >= 0.5 → 也匹配下方
      ├─────────┼─────────┼─────────┤
行 gj+1│         │  扩展↓  │         │
      └─────────┴─────────┴─────────┘

★ 落在中间 cell，但靠近右上角 → 可能同时匹配:
  中间 cell (gi, gj) + 右侧 cell (gi+1, gj) + 上方 cell (gi, gj-1)
  每个 cell 又有 3 个 anchor → 最多 3 cell × 3 anchor = 9 个正样本 / GT
```

**为什么要扩展相邻 cell？**

**问题背景**：YOLOv3 每个 GT 在每个尺度层只匹配 **IoU 最大的 1 个 anchor**，正样本极少。

```
一张图 10 个 GT × 3 个尺度 × 1 个 anchor = 30 个正样本
对比 25,200 个预测点 → 正负比 ≈ 1:840
```

正样本严重不足，导致：
- obj loss 中负样本占绝对主导，模型倾向于**全预测为背景**
- 每个 GT 只有 1 个 anchor 学习回归，**定位监督信号弱**
- recall 低，小目标尤其容易漏检

**Multi-positive 的好处：**

| 好处 | 说明 |
|------|------|
| 正样本数量 ×3~×9 | 10 个 GT 可产生 30~90 个正样本，正负比改善到 1:280~1:840 |
| 缓解正负极度不平衡 | 更多正样本 → obj loss 梯度更平衡 → 减少"全预测背景"倾向 |
| 边界目标更好学 | GT 中心靠近 cell 边界时，原 cell 可能不在目标最佳感受野中心；相邻 cell 分担学习 |
| 提升 recall | 推理时多个 cell 都能对同一 GT 产生高置信度预测，降低漏检概率 |
| 加速收敛 | 更多 box/cls 监督信号 → 定位与分类 loss 下降更快 |

**代价与应对：**

| 代价 | 应对 |
|------|------|
| 推理时同一 GT 产生多个重叠框 | **NMS** 在推理阶段去重，只保留置信度最高的框 |
| 正样本间 box 回归目标相同，可能引入轻微冗余梯度 | 实践中收益远大于代价，YOLOv4/v5 均验证有效 |

**与 YOLOv3 的对比：**

```
YOLOv1:  GT 中心 → 1 个 cell → 2 个 bbox（无 anchor）     → 正样本极少，每类互斥
YOLOv2:  GT 中心 → 1 个 cell → 5 个 anchor 中 IoU 匹配   → 引入 anchor，仍单尺度
YOLOv3:  每个 GT → 每尺度 1 个 anchor（IoU 最大）         → 正样本仍少，共 3 个/GT
YOLOv4:  同 v3 + Mosaic/CIoU 等训练策略补偿              → 靠数据增强和 loss 改进弥补
YOLOv5:  每个 GT → 每尺度 1~3 cell × 1~3 anchor           → 正样本显著增加，最多 9 个/GT/尺度
YOLOX:   取消 anchor，SimOTA 动态分配 Top-K 正样本        → 进一步灵活化
```

> **v3 → v5 标签分配改进的本质**：v4 通过 Mosaic 等"免费技巧"提升精度，但没有改变 v3 的稀疏正样本问题。v5 的 Multi-positive 从**训练信号层面**直接增加正样本，是更根本的改进。

#### 6.4.6 Step 4：正负样本的最终标签编码

**正样本标签编码：**

```
obj_target  = 1.0                          # 这里有物体
cls_target  = one_hot(class_id)            # 对应类别为 1，其余为 0
box_target  = (tx, ty, tw, th)              # GT 框相对于 anchor 的偏移（用于 CIoU loss）
```

box_target 的计算（训练时的回归目标）：

```
tx_target = gx - floor(gx)    # 或扩展 cell 对应的偏移
ty_target = gy - floor(gy)
tw_target = log(w_gt / aw)    # 宽高取 log 比值
th_target = log(h_gt / ah)
```

注意：推理时的解码公式（§5.3）与训练时的编码互为逆过程。

**负样本标签编码：**

```
obj_target  = 0.0      # 这里没有物体
cls_target  = 不计算    # 无 GT，无法定义类别
box_target  = 不计算    # 无 GT，无法定义框
```

#### 6.4.7 正负样本极度不平衡问题

```
典型场景: 25,200 个预测点，10 个 GT，~50 个正样本
正负比 ≈ 1 : 500
```

**不平衡带来的风险：**

- obj loss 被海量负样本主导 → 模型输出整体 objectness 偏低 → 漏检
- 少数正样本的 box/cls 梯度被淹没 → 定位/分类学习慢

**YOLOv5 的应对策略：**

| 策略 | 原理 |
|------|------|
| 仅正样本算 box/cls loss | 避免负样本产生无意义梯度 |
| obj loss 全体参与 | 让模型充分学习背景特征 |
| Loss 权重调节（box/obj/cls gain） | 手动平衡三项 loss 的量级 |
| AutoBalance（可选） | 自动调整 P3/P4/P5 三层的 obj 权重，防止某尺度 domination |
| Label Smoothing（可选） | 正样本 obj 目标从 1.0 软化为 0.99，负样本从 0.0 软化为 0.01，缓解过拟合 |
| Focal Loss（需手动改代码） | 降低"简单负样本"的 loss 权重，聚焦难样本 |

#### 6.4.8 完整分配流程小结

```
对于每张图的每个 GT 框:
  │
  ├─ 1. 遍历 3 个尺度层 (P3, P4, P5)
  │     └─ 每层 3 个 anchor，共 9 个候选
  │
  ├─ 2. 宽高比筛选: r < 4.0 的 anchor 保留
  │     └─ 通常 1~3 个 anchor 通过
  │
  ├─ 3. 计算 GT 中心落在哪个 grid cell (gi, gj)
  │
  ├─ 4. 相邻 cell 扩展: 根据中心偏移，最多再匹配 2 个相邻 cell
  │     └─ 每个 (cell, anchor) 组合 → 1 个正样本
  │
  └─ 5. 编码标签: obj=1, cls=one_hot, box=GT 偏移

所有未被任何 GT 匹配的 (cell, anchor) → 负样本, obj=0

最终:
  正样本 → 参与 box + obj + cls 三项 loss
  负样本 → 仅参与 obj loss
```

### 6.5 损失函数

总损失：

```
L = λ_box · L_box + λ_obj · L_obj + λ_cls · L_cls
```

#### （1）Box Loss — CIoU Loss

```
L_box = 1 - CIoU

CIoU = IoU - ρ²(b, b_gt)/c² - α·v

其中:
  IoU     = 交并比
  ρ       = 预测框与 GT 中心点距离
  c       = 最小外接矩形的对角线长度
  v       = (4/π²) · (arctan(w_gt/h_gt) - arctan(w/h))²   宽高比一致性
  α       = v / (1 - IoU + v)                            动态权重
```

**CIoU 比 IoU / DIoU 更好之处：**

- IoU：两框不重叠时梯度为 0，无法优化
- DIoU：加入中心距离，但未考虑宽高比
- CIoU：额外惩罚宽高比差异，收敛更快、定位更准

> **演进对比：Box Loss**
>
> | 版本 | Box Loss | 问题/改进 |
> |------|----------|----------|
> | **v1/v2** | MSE（坐标直接回归） | 大框和小框误差权重相同，小框定位差；对框大小不敏感 |
> | **v3** | MSE → 后期改用 IoU 系列 | 开始关注框的重叠程度而非绝对坐标差 |
> | **v4** | **CIoU Loss** | 同时考虑重叠、中心距离、宽高比，定位精度大幅提升 |
> | **v5** | CIoU（同 v4） | 完整继承 |
>
> **MSE → CIoU 的演进逻辑**：
> ```
> MSE:  预测 (100,100,50,50) vs GT (105,105,50,50) → loss 很小
>       预测 (100,100,50,50) vs GT (200,200,50,50) → loss 很大
>       但两种情况下 IoU 可能都很低！MSE 与检测质量不对齐
>
> IoU:  直接优化重叠面积，与 mAP 评估指标对齐
> DIoU: IoU + 中心点距离 → 加速收敛
> CIoU: DIoU + 宽高比一致性 → 框形状也更准
> ```

#### （2）Objectness Loss — BCE

```
L_obj = BCE(obj_pred, obj_target)

正样本: obj_target = 1.0
负样本: obj_target = 0.0
```

使用 **BCEWithLogitsLoss**（内部含 sigmoid），配合 **Label Smoothing**（默认 0.0，可设 0.01~0.1 防过拟合）。

**AutoBalance**（可选）：根据各尺度 loss 大小自动调整 P3/P4/P5 的 obj 权重，平衡不同尺度的贡献。

#### （3）Classification Loss — BCE

```
L_cls = BCE(cls_pred, cls_target)    仅对正样本计算

多类别: 每类独立 sigmoid（非 softmax），支持多标签
单类别: cls_target = 1.0
```

**为什么用 BCE 而非 CrossEntropy？**

- 检测任务中各类别**相互独立**（非互斥），BCE 更合理
- 支持 "**一个框属于多个类**" 的多标签场景

> **演进对比：Classification Loss**
>
> | 版本 | Cls Loss | 说明 |
> |------|----------|------|
> | **v1/v2** | Softmax + CrossEntropy | 假设类互斥，一个框只能分 1 类 |
> | **v3~v5** | **独立 Sigmoid + BCE** | 每个类独立判断，支持多标签；与 obj 解耦 |

#### （4）损失权重

| 超参 | 默认值 | 含义 | 调大效果 |
|------|--------|------|----------|
| box | 0.05 | 定位损失权重 | 框更准，但 cls 可能下降 |
| obj | 1.0 | 置信度损失权重 | 减少漏检，但 FP 可能增多 |
| cls | 0.5 | 分类损失权重 | 分类更准，定位可能略降 |

#### （5）多尺度 Loss 平衡（Layer Balance）

YOLOv5 对 P3/P4/P5 三层的 obj loss 有**默认权重**：

```
balance = [4.0, 1.0, 0.4]   对应 P3 / P4 / P5
```

**为什么 P3 权重最高？**

- P3 预测点最多（19,200 个），但正样本中小目标占比高、更难学
- 不加权的话 P5 的大目标 loss 会 dominate，小目标 AP 偏低
- 给 P3 更高权重 → 强迫网络更关注小目标

可选 **AutoBalance**：训练前几个 epoch 自动统计各层 loss 量级，动态调整 balance 系数。

#### （6）Loss 随输入尺寸的缩放

```python
# box loss 会按 batch size 和图像尺寸缩放
box_loss *= 3 / nl * (1.0 / batch_size)   # nl = 3 个尺度
```

保证不同 batch size 和 img_size 下 loss 量级一致，换配置训练时不需要重新调 lr。

### 6.6 训练循环关键步骤

```
for epoch in range(epochs):
    │
    ├─ 1. 学习率调度
    │     Warmup (前 3 epoch): lr 从 0 线性升到 lr0
    │     之后: 余弦退火 lr0 → lr0 × lrf
    │
    ├─ 2. 多尺度训练（可选）
    │     每个 batch 随机 img_size ∈ [0.5×S, 1.5×S]
    │     强制模型适应不同分辨率
    │
    ├─ 3. 前向传播 → 计算 loss → 反向传播
    │
    ├─ 4. EMA 更新（指数移动平均）
    │     ema_weight = 0.9999 × ema_weight + 0.0001 × current_weight
    │     验证/推理时使用 EMA 权重，更稳定
    │
    ├─ 5. 验证集评估 mAP
    │     使用 EMA 模型，计算 mAP@0.5 和 mAP@0.5:0.95
    │
    └─ 6. 保存 checkpoint
          best.pt: 验证 mAP 最高的权重
          last.pt: 最后一个 epoch 的权重
```

> **演进对比：训练策略**
>
> | 策略 | v1~v3 | v4 | v5 | 好处 |
> |------|-------|----|----|------|
> | 多尺度训练 | v2 起有 | ✓ | ✓ | 尺度鲁棒性 |
> | Mosaic | ✗ | ✓ 首次 | ✓ + close_mosaic | 丰富训练样本 |
> | CIoU Loss | ✗ | ✓ 首次 | ✓ | 定位更准 |
> | EMA | ✗ | ✗ | ✓ | 权重平滑，推理更稳定 |
> | 余弦退火 LR | ✗ | ✓ | ✓ | 后期精细收敛 |
> | Warmup | ✗ | ✓ | ✓ | 防止初期大 LR 发散 |
> | 超参进化 `--evolve` | ✗ | ✗ | ✓ | 遗传算法自动搜最优 hyp |
> | 自动 batch size | ✗ | ✗ | ✓ | 根据 GPU 显存自动适配 |
> | 混合精度 AMP | ✗ | ✗ | ✓ | 训练速度 ×2，显存减半 |

### 6.7 mAP 评估指标

训练完成后用 mAP 衡量模型精度，理解指标有助于正确解读实验结果。

**核心概念：**

```
Precision（精确率）= TP / (TP + FP)    "检出的有多少是对的"
Recall（召回率）   = TP / (TP + FN)    "对的有多少被检出"

P-R 曲线: 不同 conf 阈值下的一系列 (P, R) 点
AP（Average Precision）= P-R 曲线下面积（单个类别）
mAP = 所有类别 AP 的平均值
```

**COCO 的两个 mAP：**

| 指标 | IoU 阈值 | 含义 |
|------|----------|------|
| mAP@0.5 | 固定 0.5 | 框重叠 >50% 即算检测正确，较宽松 |
| mAP@0.5:0.95 | 0.5, 0.55, ..., 0.95 共 10 档取均值 | 对定位精度要求更高，**COCO 官方主指标** |

**mAP@0.5:0.95 更严格的原因**：只要求 IoU>0.5 的"差不多对了"不够，高 IoU 阈值（0.75、0.9）要求框**非常精确**才能算 TP，因此 mAP@0.5:0.95 通常比 mAP@0.5 低 15~20 点。

> **演进对比：精度提升轨迹（COCO val, mAP@0.5:0.95）**
>
> ```
> YOLOv1:  ~19.5   基线，证明单阶段可行
> YOLOv2:  ~21.6   +anchor +passthrough
> YOLOv3:  ~33.0   +多尺度 +FPN  (+11.4，最大飞跃)
> YOLOv4:  ~43.5   +CSP +PANet +Mosaic +CIoU  (+10.5)
> YOLOv5x: ~50.7   工程优化 + 更大模型  (+7.2)
> ```
>
> 可见 **v2→v3（多尺度）** 和 **v3→v4（结构+训练策略）** 是两次最大的精度跃升。v5 相对 v4 不是算法突破，而是工程精炼 + 模型缩放。

### 6.8 训练工程机制（原文档未展开）

以下处理不影响算法原理，但对**能否顺利训出好模型**至关重要：

#### 6.8.1 超参数文件 hyp.yaml

三套预设，按数据集规模选择：

| 文件 | 适用 | 特点 |
|------|------|------|
| `hyp.scratch-low.yaml` | 小数据集（< 1k 图） | 强增强、大 weight_decay、防过拟合 |
| `hyp.scratch-med.yaml` | 中等（1k~10k） | 折中 |
| `hyp.scratch-high.yaml` | 大数据集（COCO 级） | 默认，增强适中 |

包含 lr、momentum、各 loss gain、增强参数等 30+ 项，可用 `--evolve` 遗传算法自动搜索。

#### 6.8.2 迁移学习与冻结训练

```
阶段 1: python train.py --weights yolov5s.pt --freeze 10
        → 冻结 backbone 前 10 层，只训练 Head + Neck 后几层
        → 小数据集快速收敛，防止破坏预训练特征

阶段 2: python train.py --weights runs/train/exp/weights/best.pt
        → 解冻全部层，低 lr 全量微调
```

**权重加载规则**：`--weights` 加载时 shape 不匹配的层（如 nc 不同导致的 Detect 层）会**跳过**，其余层正常加载。

#### 6.8.3 混合精度 AMP

```
torch.cuda.amp.autocast() + GradScaler
```

- 前向/loss 用 FP16，梯度更新用 FP32
- 训练速度提升 ~2×，显存减半，精度几乎无损
- 默认开启，可用 `--noamp` 关闭

| 机制 | 命令/方式 | 作用 |
|------|----------|------|
| **DDP 多卡** | `python -m torch.distributed.run --nproc_per_node 4 train.py` | 数据并行，线性加速 |
| **SyncBN** | `--sync-bn` | 多卡同步 BN 统计，小 batch 时更稳定 |
| **梯度累积** | `--accumulate 4` | 等效 batch ×4，显存不够时用 |
| **AutoBatch** | `--batch-size -1` | 自动探测 GPU 最大可用 batch size |

#### 6.8.5 EMA 详解

```python
# 每个 step 更新（decay=0.9999）
ema_attr = 0.9999 * ema_attr + 0.0001 * model_attr

# 验证/保存 best.pt 时用 EMA 权重，不用当前训练权重
```

**为什么 EMA 有效？** SGD 每步更新有噪声，EMA 相当于对最近 ~10000 步权重取平均，去掉噪声波动，验证 mAP 通常高 0.5~1 点。`best.pt` 保存的是 EMA 权重。

#### 6.8.6 早停与断点续训

| 机制 | 参数 | 说明 |
|------|------|------|
| **早停** | `--patience 100` | 100 epoch 无 mAP 提升则停止，防过拟合+省时间 |
| **断点续训** | `--resume` | 从 last.pt 恢复 epoch、optimizer、EMA、lr scheduler |
| **保存策略** | 每 epoch 存 last.pt；mAP 最高时存 best.pt | best 用于部署，last 用于 resume |

#### 6.8.7 超参进化 `--evolve`

```
遗传算法流程:
  1. 初始化种群（多套 hyp）
  2. 每套 hyp 训练若干 epoch，用 mAP 作为 fitness
  3. 选择、交叉、变异 → 下一代 hyp
  4. 迭代 300 代（默认）
  → 输出 fitness 最高的 hyp.yaml
```

适合**不确定超参**的新数据集，但耗时极大（300 × 训练时间）。

### 6.9 验证流程（val.py）

训练中的 mAP 评估并非简单"算 IoU"，有一套完整匹配流程：

```
Step 1: 模型在验证集上推理（letterbox + 解码 + NMS）
Step 2: 预测框与 GT 框按类别分组
Step 3: 按 conf 降序，逐个预测框匹配 GT
        - IoU > 阈值 且 GT 未被匹配 → TP
        - IoU > 阈值 但 GT 已被匹配 → FP（重复检测）
        - IoU < 阈值 → FP
        - 未匹配的 GT → FN
Step 4: 在 10 个 IoU 阈值 (0.5~0.95) 下分别统计 TP/FP
Step 5: 绘制 P-R 曲线 → 计算 AP → 取均值得 mAP
```

**验证输出（runs/val/exp/）：**

| 输出 | 内容 |
|------|------|
| `confusion_matrix.png` | 混淆矩阵，看哪些类容易互混 |
| `PR_curve.png` | 各类 P-R 曲线 |
| `F1_curve.png` | F1-置信度曲线，辅助选 conf_thres |
| `predictions.json` | COCO 格式，可用 pycocotools 评估 |
| `_batch*.jpg` | 验证集预测可视化 |

**选 conf_thres 的技巧**：看 F1_curve 峰值对应的 conf，often 0.25~0.4，可作为部署默认值。

### 7.2 NMS（非极大值抑制）—— 详解

#### 7.2.1 为什么需要 NMS？

训练时 Multi-positive 策略（§6.4.5）让**多个 cell、多个 anchor** 同时学习同一个 GT。推理时，这些预测点都会对同一目标输出高置信度框：

```
同一个"人"可能被检测到:
  - P3 层 cell (32, 45) anchor-1  → 框 A, conf=0.92
  - P3 层 cell (32, 46) anchor-1  → 框 B, conf=0.87  （相邻 cell）
  - P3 层 cell (32, 45) anchor-2  → 框 C, conf=0.78  （同 cell 不同 anchor）
  - P4 层 cell (16, 22) anchor-1  → 框 D, conf=0.85  （跨尺度）
```

不用 NMS → 一个目标输出 4 个重叠框 → 结果不可用。

NMS 的作用：**对同一目标的多个重叠预测，只保留置信度最高的那个，抑制其余。**

```
NMS 前:                          NMS 后:
┌──────────┐                     ┌──────────┐
│ ┌──────┐ │                     │          │
│ │ A    │ │  conf=0.92 ← 保留   │    A     │  只留一个
│ │ ┌────┤ │                     │          │
│ └─┤ B  │ │  conf=0.87 ← 抑制   └──────────┘
│   └────┘ │
│  ┌───┐   │
│  │ C │   │  conf=0.78 ← 抑制
│  └───┘   │
└──────────┘
```

**NMS 是训练策略（Multi-positive）在推理端的必要配套**：训练时故意制造多个正样本提升 recall，推理时用 NMS 消除冗余。

#### 7.2.2 IoU：NMS 的判定依据

```
IoU = 交集面积 / 并集面积

  ┌────────┐
  │   A    │
  │    ┌───┼───┐
  └─── │───┘   │ B
       └───────┘

  IoU = Area(A ∩ B) / Area(A ∪ B)    范围 [0, 1]
  IoU = 0   → 两框完全不重叠
  IoU = 1   → 两框完全重合
  IoU > 0.5 → 通常认为检测的是同一个目标
```

#### 7.2.3 经典 NMS 算法（逐步推演）

**输入：** 所有 conf > conf_thres 的候选框，每个框 = `(x1, y1, x2, y2, conf, cls)`

**算法：**

```
1. 按 conf 从高到低排序所有候选框
2. 取 conf 最高的框 → 加入"保留列表"
3. 计算该框与剩余所有框的 IoU
4. 删除 IoU > iou_thres 的框（认为它们检测的是同一目标）
5. 重复 2~4，直到没有剩余框
6. 输出"保留列表"
```

**具体数值示例：**

```
5 个候选框（同一类别）:
  框1: conf=0.92, [100, 100, 200, 300]
  框2: conf=0.87, [105, 105, 195, 295]   ← 与框1 高度重叠
  框3: conf=0.85, [110, 110, 190, 290]   ← 与框1 高度重叠
  框4: conf=0.78, [400, 400, 500, 600]   ← 完全独立的另一个目标
  框5: conf=0.65, [405, 405, 495, 595]   ← 与框4 高度重叠

iou_thres = 0.45

Round 1: 取框1 (0.92) → 保留
         框2 IoU(框1,框2) = 0.82 > 0.45 → 删除
         框3 IoU(框1,框3) = 0.71 > 0.45 → 删除
         框4 IoU(框1,框4) = 0.00 → 保留
         框5 IoU(框1,框5) = 0.00 → 保留

Round 2: 剩余 [框4, 框5]，取框4 (0.85) → 保留
         框5 IoU(框4,框5) = 0.79 > 0.45 → 删除

最终输出: [框1, 框4]  →  2 个目标，各 1 个框 ✓
```

#### 7.2.4 YOLOv5 中 NMS 的完整实现流程

源码位于 `utils/general.py` 的 `non_max_suppression()`，实际执行分 **4 步**：

```
Step 1: 合并三个尺度的输出
  P3 (80×80×3) + P4 (40×40×3) + P5 (20×20×3)
  → 展平为 (1, 25200, 5+nc) 的统一候选集

Step 2: 坐标解码 + 置信度过滤
  对每个预测点:
    解码 (tx,ty,tw,th) → (x1,y1,x2,y2)  像素坐标
    conf = obj_conf × cls_conf
    保留 conf > conf_thres (默认 0.25) 的框
  → 通常从 25,200 个缩减到 ~300~3,000 个

Step 3: 按类别分组 NMS
  对每个类别独立执行 NMS（class-aware NMS）
  使用 torchvision.ops.nms(boxes, scores, iou_thres)
  → GPU 加速，O(n log n) 复杂度

Step 4: 截断
  保留 conf 最高的 max_det 个框（默认 300）
  → 防止极端情况下输出过多框
```

**伪代码：**

```python
def non_max_suppression(prediction, conf_thres=0.25, iou_thres=0.45, max_det=300):
    # Step 1: 解码 + 过滤
    candidates = []
    for each pred in prediction:          # 遍历 25200 个预测点
        conf = pred.obj * pred.cls_max    # 最终置信度
        if conf < conf_thres:
            continue                      # 低置信度直接丢弃
        box = decode_box(pred)            # §5.3 解码公式
        candidates.append(box, conf, cls)

    # Step 2: 按类别分组 NMS
    output = []
    for cls_id in unique_classes:
        cls_boxes = [c for c in candidates if c.cls == cls_id]
        cls_boxes.sort(by=conf, descending=True)   # 按 conf 降序

        keep = []
        while cls_boxes not empty:
            best = cls_boxes.pop(0)       # 取 conf 最高的
            keep.append(best)
            cls_boxes = [b for b in cls_boxes
                         if IoU(best, b) <= iou_thres]  # 抑制重叠框
        output.extend(keep)

    # Step 3: 截断
    output.sort(by=conf, descending=True)
    return output[:max_det]
```

#### 7.2.5 关键参数详解

| 参数 | 默认值 | 作用 | 调大效果 | 调小效果 |
|------|--------|------|----------|----------|
| `conf_thres` | 0.25 | NMS **前**的置信度门槛 | 更少候选框进入 NMS，FP↓，可能漏检↑ | 更多候选框进入 NMS，recall↑，FP↑ |
| `iou_thres` | 0.45 | 两框 IoU 超过此值则抑制低分框 | 更宽松，允许更多重叠框共存（重复检测↑） | 更严格，重叠框更容易被抑制（可能误删相邻目标） |
| `max_det` | 300 | 单图最多输出框数 | 允许更多检测（密集场景） | 截断更多框 |
| `agnostic_nms` | False | 是否忽略类别，跨类 NMS | — | True 时所有类一起做 NMS |

**conf_thres 与 iou_thres 的分工：**

```
conf_thres → 控制"要不要进入 NMS"（召回率 vs 误检率的第一道门）
iou_thres  → 控制"重叠框留几个"（去重力度）

两者独立调节:
  漏检多 → 降低 conf_thres（如 0.15）
  重复框多 → 降低 iou_thres（如 0.35）
  相邻同类目标被误删 → 提高 iou_thres（如 0.55）
```

#### 7.2.6 Class-aware NMS vs Class-agnostic NMS

**Class-aware（YOLOv5 默认）：**

```
每个类别独立做 NMS
  "猫" 的框只和 "猫" 的框比 IoU
  "狗" 的框只和 "狗" 的框比 IoU
  猫和狗即使重叠也不互相 suppress
```

**Class-agnostic（`--agnostic-nms`）：**

```
所有类别混在一起做 NMS
  任意两框 IoU 超阈值就 suppress
```

**为什么默认用 class-aware？**

```
场景: 一只猫趴在一只狗身上

Class-aware:  猫框和狗框各自保留 ✓
Class-agnostic: IoU 可能 > 0.45 → 只保留 conf 高的那个 ✗ 漏掉另一个
```

**何时用 class-agnostic？** 单类别检测（如人脸检测 nc=1），或类别间不可能重叠的场景。

#### 7.2.7 NMS 变体

经典 NMS 的硬删除策略在**密集场景**下可能误删相邻目标。常见改进：

| 变体 | 原理 | 优势 | 劣势 |
|------|------|------|------|
| **Classic NMS** | IoU 超阈值 → 直接删除 | 简单、快速 | 密集目标可能误删 |
| **Soft-NMS** | IoU 超阈值 → 降低 conf（乘以衰减因子），不直接删除 | 密集场景 recall 更高 | 可能保留低质量框 |
| **DIoU-NMS** | 用 DIoU 替代 IoU 做抑制判定 | 中心点距离远的不 suppress，减少误删 | 计算量略增 |
| **Weighted NMS (WBF)** | 重叠框坐标加权平均 | 框定位更准，适合模型集成 | 不适合单模型实时推理 |

**Soft-NMS 核心思想：**

```
Classic NMS:  IoU > 0.45 → conf 直接置 0（删除）
Soft-NMS:     IoU > 0.45 → conf = conf × (1 - IoU)  （衰减但不删除）
              下一轮如果 conf 仍高于阈值 → 仍有机会被保留
```

适用场景：人群检测、货架商品检测等**同类目标密集排列**的场景。

#### 7.2.8 常见问题与调参指南

| 现象 | 可能原因 | 解决方案 |
|------|----------|----------|
| 同一目标出现多个框 | iou_thres 太高 | 降低到 0.35~0.40 |
| 相邻同类目标只检测到一个 | iou_thres 太低 | 提高到 0.50~0.60 |
| 大量误检（FP 高） | conf_thres 太低 | 提高到 0.35~0.50 |
| 漏检多（FN 高） | conf_thres 太高 | 降低到 0.10~0.20 |
| 小目标重复检测 | 跨尺度重复（P3+P4 都检测到） | 降低 iou_thres 或提高 conf_thres |
| 推理速度慢 | 候选框太多进入 NMS | 提高 conf_thres 减少候选数 |

#### 7.2.9 训练与推理的完整闭环

```
训练端                              推理端
────────                            ────────
Multi-positive:                     NMS:
  1 个 GT → 多个正样本                1 个 GT → 多个候选框
  提升 recall 训练信号                只保留 conf 最高的 1 个框
  加速收敛                            消除冗余输出

两者配合:
  训练"宽进" → 让更多预测点学会检测目标
  推理"严出" → NMS 保证每个目标只输出一个框
```

这是 YOLO 系列的经典设计哲学：**训练时宽松匹配，推理时严格去重**。

> **演进对比：NMS**
>
> | 版本 | NMS | 说明 |
> |------|-----|------|
> | **v1~v5** | 经典 NMS | 所有 YOLO 版本推理都依赖 NMS 去重 |
> | **v4** | 同 v1~v3 | v4 论文还提到 CIoU-NMS，但实际默认仍用 IoU-NMS |
> | **v5** | torchvision GPU NMS + class-aware | 实现更高效，支持 per-class NMS |
>
> NMS 从 v1 到 v5 没有本质变化——因为**密集预测 + NMS 去重**这一范式在所有 YOLO 版本中都是推理的标准后处理。变化的是训练端如何产生候选框（从 98 个到 25,200 个），NMS 负责最后一道筛选。

### 7.4 推理优化机制（原文档未展开）

#### 7.4.1 Conv + BN 融合（--fuse）

```
推理前: Conv(x) → BN(x) → SiLU(x)     两次运算
融合后: FusedConv(x) → SiLU(x)        一次运算

原理: 推理时 BN 参数固定，可数学合并进 Conv 的 weight 和 bias
```

```

**好处**：减少内存访问，推理加速 ~5~10%，无精度损失。部署前几乎总是应该 fuse。

#### 7.4.2 半精度 FP16 推理

```bash

```

- 模型和输入都转为 FP16
- GPU 推理加速 ~1.5~2×，显存减半
- 精度损失通常 < 0.1 mAP，实时场景常用

#### 7.4.3 测试时增强 TTA

```bash
python val.py --weights best.pt --data data.yaml --augment
```

TTA 流程：

```
原图 640×640        → 预测 → 框集合 A
原图 320×320        → 预测 → 框集合 B  → 坐标缩放到 640
原图 1280×1280       → 预测 → 框集合 C  → 坐标缩放到 640
原图 640×640 翻转    → 预测 → 框集合 D  → 坐标反翻转
    ↓
合并 A+B+C+D → NMS 去重 → 最终结果
```

**代价**：推理时间 ×4（4 种变换），精度通常 +0.5~1.5 mAP。**仅验证/比赛用，生产部署一般不用。**

```

逐帧 letterbox → 推理 → NMS → 坐标还原 → 绘制，无额外时序建模（纯逐帧检测）。

### 7.5 YOLOv5 扩展任务（同仓库，不同 Head）

YOLOv5 仓库不仅做检测，还有扩展版本，处理流程各有差异：

| 版本 | 任务 | Head 差异 | 额外输出 |
|------|------|----------|----------|
| **detect** | 目标检测 | 标准 Detect | bbox + cls |
| **segment** | 实例分割 | Segment = Detect + 掩码分支 | bbox + cls + **mask coefficients** |
| **classify** | 图像分类 | Classify head（无 Detect） | 类别概率 |

Segment 在 Detect 基础上增加 **Proto 模块**（生成 32 个基础掩码）和 **mask 系数**（每个检测框 32 维），最终 mask = sigmoid(系数 × Proto)。

## 8. 精度提升方向与结构改进

### 8.1 优先级

```
数据质量 → 训练策略 → 模型结构 → 后处理
（决定上限）  （低成本）   （中等成本）  （锦上添花）
```

### 8.2 数据层面

| 手段 | 原理 | 适用场景 |
|------|------|----------|
| 清洗标注 | 消除噪声标签 | 所有场景，优先做 |
| Copy-Paste | 实例级粘贴，增加小目标样本 | 小目标检测 |
| 重新聚类 anchor | 使 anchor 与数据尺度匹配 | 自定义数据集必做 |
| 提高输入分辨率 | P3 特征图更大，小目标信息更多 | 小目标、精度优先 |

### 8.3 训练策略

| 手段 | 原理 | 预期收益 |
|------|------|----------|
| EMA | 权重滑动平均，平滑噪声 | +0.5~1 mAP |
| 更长 epoch + close_mosaic | 后期正常分布微调 | +0.5~1 mAP |
| 多尺度训练 | 尺度鲁棒性 | +0.3~0.8 mAP |
| COCO 预训练 | 迁移学习 | 小数据集 +5~15 mAP |
| 超参进化 `--evolve` | 遗传算法搜索最优 hyp | 因数据集而异 |

### 8.4 结构改进（按模块）

**Backbone 改进：**

| 方法 | 插入位置 | 原理 |
|------|----------|------|
| SE / CBAM / ECA | C3 之后 | 通道/空间注意力，让网络关注重要特征 |
| RepConv | 替换普通 Conv | 训练多分支、推理合并为单路，精度↑速度不变 |
| 更深/更宽 | depth/width multiple | 直接 scaling，最简单粗暴 |

**Neck 改进：**

| 方法 | 替换对象 | 原理 |
|------|----------|------|
| BiFPN | PANet | 加权融合，重复堆叠，EfficientDet 验证有效 |
| 增加 P2 层 | 新增 stride=4 的检测头 | P2 分辨率 160×160，小目标 AP 显著提升 |
| ASFF | 融合节点 | 学习空间自适应权重 |

**Head 改进：**

| 方法 | 原理 | 参考 |
|------|------|------|
| Decoupled Head | cls 和 reg 用独立分支 | YOLOX，缓解任务冲突 |
| SimOTA 标签分配 | 动态匹配，不用固定 anchor | YOLOX，减少超参 |
| DFL (Distribution Focal Loss) | 回归框的离散分布 | YOLOv8 |

### 8.5 后处理

| 手段 | 说明 |
|------|------|
| 降低 conf_thres | 提升 recall，适合漏检多的场景 |
| 降低 iou_thres | 适合密集目标（如人群、货架） |
| TTA | 多尺度+翻转推理取并集，+0.5~1.5 mAP |
| 模型集成 WBF | 多模型框加权融合 |
